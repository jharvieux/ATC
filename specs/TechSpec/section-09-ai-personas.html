Section 9 — AI Personas

Six AI personas serve customers. Each has distinct expertise, voice, and visual identity. Personas are globally defined; tenants can override display name (Pro and Agency tiers) and append custom instructions (Agency only).

9.2 Persona Selection ¶

  • Customer can manually pick a persona from ‘Meet our advisors’ page
  • AI router selects appropriate persona based on customer’s initial query topic (defaults to Marcus if unclear)
  • AI may suggest mid-conversation handoff: ‘This is more in Maya’s wheelhouse — should I get her involved?’
  • Customer can override and stay with current persona

9.3 System Prompt Architecture ¶

Each persona’s system prompt is built from three layers, in order:

  • Base persona block — character, voice, expertise, visual identity, base instructions
  • Platform constraints — disclosure rules, prohibited topics (medical/legal/financial advice), escalation triggers
  • Tenant addendum (Agency tier only) — appended after platform constraints; Haiku-screened for safety before save

The full prompt is cached (Anthropic prompt caching) to reduce inference cost on subsequent turns.

9.4 Persona Base Block Structure ¶

Each base block establishes:

  • Character: name, background, voice (warm professional / direct / playful)
  • Expertise area: regional and topical focus
  • Anti-instructions: never claim to be human, never give medical/legal/financial advice, never make commitments on behalf of host
  • Tone calibration placeholder: filled at runtime per §24 tone matching
  • Disclosure pattern: how to introduce self when asked

9.6 Tool Use ¶

Personas have access to tools via Anthropic’s tool use API:

  • search_host_inventory — query host adapter for cruise availability
  • get_customer_context — fetch CRM + memory for current customer
  • generate_quote — create a quote line item set
  • collect_booking_details — initiate booking flow with pre-fills
  • escalate_to_human — surface to tenant’s supervisor
  • update_memory — write to customer_memories (with consent check)

9.7 Disclosure Rules ¶

AI personas always disclose AI nature when asked. Persistent UI disclosure (§24) says ‘AI-assisted chat’. State-specific AI disclosure laws (California, Illinois, Utah, New York) covered by the AI Liability Disclaimer (§17.6) that every user accepts.

9.9 Streaming via SSE ¶

Chat responses stream via Server-Sent Events. Client subscribes to /api/chat with the message; server streams response chunks. Reconnect supported via Last-Event-ID header.

9.10.1 What disabled actually disables ¶

ai_mode = 'disabled' means no customer-facing AI chat responses. It does NOT mean zero AI processing. The following continue to run regardless of ai_mode:

AI processRuns when ai_mode = disabled?Why
Customer chat persona responseNOThe point of disabled mode

Memory extraction from conversations (§11.2)YESConversations still happen; memory captures customer facts the agent typed
Persona addendum Haiku screening (§16.6)YESTenant may still configure personas for future use
RAG ingestion pipeline normalization (§22)YESTenant may still submit content for their corpus
Abuse signal screening on RAG submissions (§22.4)YESPlatform protection regardless of tenant mode
Forum moderation (§19.3)YESTenant participation in group forums
Supervisor preflight checksNO (no AI response to check)N/A
Pre-cruise email rendering with personalization (§23.4)YES (if email send enabled)Emails are platform-orchestrated, not customer-chat

AI Mode is a customer-chat-scoped control, not a platform-wide AI off switch.

9.10.2 Tenant-facing UI requirements ¶

The ai_mode configuration screen MUST:

  • Show the three modes with the behavior description from the §9.10 table above.
  • Show an expandable "What does disabled NOT cover?" section reproducing the §9.10.1 table.
  • Show estimated monthly AI cost ranges for each mode at the tenant's current usage pattern (per §27.12 cost attribution).
  • For disabled specifically: show a callout "If you need TRULY zero AI processing — including memory extraction and persona screening — see Background AI Settings below."

9.10.3 Background AI Settings (separate toggle) ¶

For tenants who want zero AI processing of any kind, a separate "Background AI" toggle exists. Default: ON. When OFF:

  • Memory extraction does not run.
  • Persona addendums cannot be saved (Haiku screening required).
  • RAG ingestion content normalization runs with reduced AI (basic rule-based normalization only; PII detection still runs via the zero-tolerance pipeline per §22.4).
  • Pre-cruise email rendering uses template-only personalization (no AI-generated narrative).
  • Forum moderation falls back to coordinator-only (no Haiku screening — coordinator must approve every message).

Schema addition:

ALTER TABLE public.tenants
  ADD COLUMN background_ai_enabled BOOLEAN NOT NULL DEFAULT TRUE;

Tenant UI banner when Background AI is OFF:

"Background AI is OFF. Some platform features have reduced functionality:

- Customer memory is not auto-extracted from conversations.
- You cannot configure persona positioning (requires AI screening).
- Pre-cruise emails use generic templates only.
- Group forum moderation requires manual coordinator approval for every message.

[Turn Background AI back on] [Learn more]"

This is a niche setting. Most tenants will leave it ON. The toggle exists for tenants with strict compliance requirements who need to assert "no AI processing of customer data at all."

9.10.4 The trap §A.13 warned about ¶

§A.13's anti-pattern note ("letting ai_mode = 'disabled' mean 'no AI calls ever'") is addressed by §9.10.1 above. The §9.10 configuration screen makes the distinction explicit so tenants choosing disabled are not surprised by AI-related charges on their bill.

Calls Worth Flagging

  • Most tenants who choose disabled actually want draft_only. Tenant onboarding (§15) should ask about the underlying goal.
  • The Background AI toggle defaults ON. Off should be a conscious decision.
  • Estimated monthly cost ranges in the UI require §27.12 cost attribution data. For new tenants, "varies based on usage" is acceptable.
